## 2. 提问习惯（用户侧）

- **总回合 11,015**，其中中文回合 53%（5,871）——**中英混用、中文略多**
- 输入长度：p50 = **73 字符**（极简短指令），p90 = 1,280；**最大 271KB**（存在巨量粘贴——日志/报错整段贴入）
- images 附加、additional_context：**0 次**——纯文字交互，从未用截图
- `trusted-tools.json`：`trustAll: true` + bash 单独授权 → **用户信任偏好极宽松**，讨厌打断

**关键行为模式**（相邻调用序列）：
- `execute_bash → execute_bash`（1,875 次）——**连续 bash 是主流工作态**（部署/运维型对话）
- `fs_read → fs_write`（494）远大于首手 `fs_write`（仅 1 个会话首工具是 fs_write）——**先读后写的纪律非常稳定**
- `fs_write → fs_write`（836）与 `fs_write → fs_read`（237）——成批编辑后回读校验
- 首工具分布：fs_read 65 · execute_bash 16 ——**开局先读文档/现状，不盲改**
- 子代理、技能、code 工具几乎不用（≤2 会话）——**单线对话+直接工具的心智模型**

## 4. 上下文管理

- 单会话上下文峰值：p50 = **10.8%** · p90 = 54.4%（大多数会话远未逼近上限）
- 逐回合 p50 = 20.1%，max 100%（到达过顶点）
- **96/96 会话都有 `valid_history_range`**（转录裁剪是 kiro 的常态机制，不是异常路径）
- 11/96 会话留有 `latest_summary`（压缩摘要发生过，但低频）
- context_manager 常载文件（96/96 一致）：`AmazonQ.md`、`AGENTS.md`、`README.md`、`.kiro/skills/*/SKILL.md`、`~/.kiro/skills/*/SKILL.md`，上限 **150,000 字符**
- file_line_tracker：69/96 会话启用（追踪已读文件的行号新鲜度）

## 5. 时延特征

- 回合总时长（请求起→流结束）：p50 = **10.8s** · p90 = 36.1s
- TTFT 字段存在但普遍为空（kiro 记录了字段、没填值）
